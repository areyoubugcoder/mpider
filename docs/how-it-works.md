# 当前工作台的实现原理

本文对应最新 Windows 原生工作台：监测登记与文章采集分离。操作步骤见 [README](../README.md)，协议细节见[会话与游标](wechat-session-protocol.md)。

## 监测、首页同步与历史采集

1. 用户开启主页识别，再在已登录微信中手动打开主页。Python/Frida 校验模块摘要及函数指纹，关联原生请求与回调，核对公众号身份。
2. 监测登记名称、首页游标与会话材料，不自动把文章入库或创建历史任务。会话及原始证据使用当前 Windows 用户 DPAPI 保存，普通前端只接收状态和元数据。
3. 用户在该公众号行点击“同步最新文章（首页）”，创建独立首页任务，使用最新可用会话发无分页游标的首页请求。认证与业务核对通过后才提交文章和当前游标，不覆盖历史检查点或缓冲。
4. “采集历史文章”单独选择篇数或截止日期。任务先消费已经获取页面的剩余文章，再从历史检查点翻页；工作进程构造并认证加密请求/响应，Rust 在事务内提交文章、游标链与进度。

首页快照、当前游标和历史检查点分别维护。成功获取新游标才更新当前指针；失败或实验复测不改写旧游标的首次获取时间，不能把请求成功但新入库为0解释成没有取得页面。

## 会话更新与自动继续

首页/历史任务首次需要新会话时，后台保留任务并启动监测。监测就绪后提示用户手动打开目标公众号主页；同一监测运行中、恢复请求后发起的目标首页交付完整新会话，才在事务中恢复原任务。仅收到首页、收到其他公众号或迟到的旧事件都不足以触发恢复。

程序不搜索、点击、刷新或改变微信窗口，不通过定时请求主页保活。新会话仍失败时停止自动循环，提供“更新会话并继续”。用户暂停、取消、关闭监测或应用重启会撤销自动继续意图；重启不静默附加微信。固定会话实验不会自动换会话。

## 正文、图片和导出

列表任务只保存文章元数据。用户另行发起单篇、勾选或整号下载，固定文章集合进入统一 FIFO 队列，已下载或已入队文章被排除；正文、图片分别遵循请求策略并复用本地缓存。

`article-md` 将 HTML 转换为 Markdown。阅读器清洗脚本、事件属性与远程资源，使用已保存图片；文章库按非空本地 Markdown 判断正文是否已下载。未下载项显示下载，已下载项显示阅读和导出，原文入口保留。

单篇、批量及整号导出都要求目标文章已有正文，在打开目录选择器前与写入前校验。导出不隐式采集，同时写入 Markdown、经过清洗的离线 HTML、已保存图片与缺图清单，详见[文章导出](article-export.md)。文章 ZIP 归档已移除，旧文件与记录保留；Windows 程序的便携 ZIP 是独立的发行产物。

## 调度、分页与请求策略

- 首页、历史与实验共用列表锁、持久化预算和冷却；独立请求记账成功后才许可发送。监测等待本身不发请求，用户通过微信发出的已观察请求另行记录，软件不能控制微信的全部后台流量。
- 默认列表间隔90–120秒、滚动24小时预算60次；正文/图片间隔各1000ms、并发各4，均可配置。这些不是平台认可的安全额度。
- HTTP 429和明确频率信号触发共享冷却；5xx、会话过期、认证失败和疑似游标失效分别处理。
- 任务分首页同步、历史采集、正文下载三个标签。列表默认每页10条；数据库分页计算完整匹配总数，不能把快照上限当成全部记录。
- 底栏显示监测状态及未结束任务的正文/历史进度；所有任务结束后隐藏相应进度。桌面与诊断入口共享数据目录锁，避免重复调度。

## 实验与安全边界

实验室默认隐藏，在设置开启后可固定游标与会话定时验证，响应只做证据、不推进正式历史检查点。关闭入口不删除实验或停止已启动的实验。会话过期只截断测量，不能据此认定游标失效。

会话与游标的有效期分别判断；更新会话后可尝试沿原检查点继续。单次成功不能证明统一有效期或长期稳定性。

当前仅验证微信4.1.15.56 x64的模块和函数指纹。原生模式不安装根证书、不切换系统代理；Frida附加已有微信退出记录，长期稳定性仍需验证。会话与原始协议证据受DPAPI保护，文章、日志和普通导出由用户自行保护，详见[安全政策](../SECURITY.md)。

代码分工：`frontend/`为React界面，`src-tauri/`为IPC和桌面壳，`crates/core/src/workbench/`管理调度、恢复、下载与实验，`crates/core/src/store/`是数据库入口，`native/`提供观察与会话协议工作进程。协议细节见[会话与游标](wechat-session-protocol.md)。
