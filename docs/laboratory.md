# 实验室说明

## 用途与开启方式

实验室用于观察同一个历史翻页游标能否继续使用，区分游标不可复用、会话过期和环境故障。普通文章采集不需要开启它，它也不能测出账号的安全采集配额。

在“系统设置 → 系统配置”开启“显示实验室”，再从左侧进入。先在公众号页开启监测，在微信手动打开目标公众号主页，等待游标和完整会话登记。

## 如何开始一次验证

1. 进入“新建实验”，选择已有游标的公众号。默认固定该公众号最新会话，也可选择获取游标时的原会话；启动后本次实验不会自动切换会话。
2. 按需要选择“立即检查”、24 小时观察、快速试验或自定义时点。自定义输入的是实验开始后经过的小时数，例如 `0.5,1,2`；自动添加即时基线，未来时点最多 24 个、每个大于 0 且不超过 24 小时。
3. 点击开始后会发送真实列表请求。后续时点继续验证固定游标，失败确认最多额外发起 3 次对照；所有请求共享列表间隔、预算与冷却，不是离线模拟。

## 怎样理解结果

- **已证实可用年龄**：原游标在该年龄成功取得有效页面，证明当时仍可用。当前年龄持续增长，不等于已经验证到这个年龄。
- **确认不可复用**：同会话下首页和新游标对照成功，原游标重复失败，才能在本次验证范围内确认；不能据此推算精确到期时刻。
- **会话过期或认证失败**：说明会话阻断测量，不代表游标到期。已有成功证据保留；取得新会话后，可对同一旧游标创建新实验，原实验记录不变。
- **缺测、超时或网络故障**：没有足够证据，不能当作游标失效。计划时间与实际请求时间分开展示。

反复使用可能影响服务端有效期，因此本实验观察的是该复用频率下的结果，不是闲置寿命或统一 TTL。已有约 33 小时的成功复用样本，也不能推广到所有公众号。

## 会不会影响正式采集与后台任务？

固定游标实验只保存验证证据，不把返回文章写入正式文章库，不推进正式历史检查点，也不重置旧游标的获取时间。但它会消耗共享请求预算，可能让其它列表任务等待。

**“获取下一页”是另一种真实采集操作**，会创建单页任务并可能入库文章、更新当前游标；不要把它当成不改变采集数据的实验检查。

关闭主窗口会收起到托盘；关闭“显示实验室”只隐藏入口，已有实验和后台进度保留。要停止验证，请在实验过程中点击“终止实验，保留已取得证据”。休眠、断网、预算不足可能造成等待或缺测，不能靠重启补造成功样本。

## 报告和隐私

在实验过程中可以查看时间线、对照请求与本实验系统日志，下载实验数据，或生成并打开报告。报告可能包含公众号名称、时间、请求标识及本地证据路径，分享前仍需检查和脱敏。

原始会话、游标和协议材料受当前 Windows 用户 DPAPI 保护，不应上传数据库、会话文件、原始抓包或整个应用数据目录。实验不提供免封控保证，Frida 稳定性和微信版本限制与普通采集相同。
