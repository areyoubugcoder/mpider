# 系统日志

工作台左侧“系统日志”汇总应用生命周期、公众号监测、文章采集、游标实验、正文及图片下载、数据导出、数据存储、请求策略及保留的旧流程日志。新日志从本版本开始记录，旧日志仍可查询；旧任务未保存的响应篇数保持未知，不根据新增篇数倒推。

日志持久化到原 SQLite `app_log` 表，新增 `context` JSON 列，旧库自动迁移，不使用外键。日志保留近3天，最多50000条；应用启动、日志总线和工作台定期写入时清理更旧记录。轮询、倒计时及未获得许可的重复等待不反复入库，避免淹没关键事件。

## 记录内容

|业务模块|关键事件及分析数据|
|---|---|
|应用|启动、退出、界面操作异常、未捕获异常、拒绝的 Promise；有限分类及脱敏原因|
|公众号监测|观察器创建/状态/加载卸载阶段、主页响应及会话就绪；识别轮次、请求ID、公众号、返回篇数、游标ID|
|文章采集|任务创建、暂停、继续、取消、进度、请求许可/结果、页面入库、当前游标变化；任务/请求ID、公众号、游标前后ID、请求时年龄、返回篇数、新入库篇数、页码、结束标记|
|游标实验|固定实验创建/状态及每个验证样本；实验/请求ID、游标ID、年龄、计划时间、角色及结果|
|正文下载|去重入队回执、任务进度/状态、正文/图片请求及内容判定、单篇处理结果；任务/文章/请求ID、公众号、HTTP状态、耗时、跳过/失败/缺图数|
|数据导出|Markdown及系统日志导出完成；格式、篇数/条数与正文完整性；保存对话框取消不生成成功记录|
|数据存储|数据库就绪、日志导出写入失败、持久化任务恢复状态|
|请求策略|策略版本、列表/正文/图片间隔、列表预算及全局冷却截止时间|

列表任务中的 `completed` 是计入历史目标的篇数；`received_articles` 是响应实际返回的篇数；`new_articles` 是新增数据库行数。三者含义不同。手动下一页成功时即使文章全部已存在，也会显示“已获取1页，返回N篇，新入库0篇”。成功取得不同游标才切换计龄起点，旧游标的 `observed_at` 不变；失败日志包含 `age_reset=false`。固定实验不推进生产游标。

工作台状态变更与对应关键日志在同一个 Store 事务中提交；日志写入失败时业务变更回滚，避免留下没有日志的成功状态。并行下载显式记录任务/文章/请求关联，不依赖全局任务上下文。HTTP返回成功日志不代表内容已经入库，页面保存、内容判定和文章处理结果分别记录。

分析字段仅接受允许列表中的标量；密钥、原始游标、会话文件、完整协议报文和资源链接不写入结构化日志。可读说明和异常原因对参数/JSON中的敏感字段及HTTP链接再次脱敏；导出旧日志时也脱敏。真实协议证据仍保留在受保护的私有文件中。

## 筛选与导出

筛选标签统一放在控件上方，自动刷新与导出格式也使用相同标签布局。业务模块只保留当前工作台实际写入的应用、公众号监测、文章采集、游标实验、正文下载、数据导出、数据存储、请求策略和列表请求。任务状态属于对应的文章采集或正文下载模块，独立的旧“任务”项不再列入；代理、RPA、凭证接力、续期、上报、补采、巡检的旧流程筛选项也移除。旧日志保留，在“全部模块”与导出中仍可查看。

可组合业务模块、精确日志级别、起止时间、关键字和任务ID。关键字在整个筛选范围的说明及结构化字段中查询，先筛选再分页，不只搜索当前页。列表按日志ID倒序，默认每页10条，可选20/50/100条，显示总条数与数字页码；翻到旧页后暂停自动刷新，首页可每2秒刷新。数据库读失败明确显示错误，不作为“没有日志”。

“导出系统日志”使用原生保存对话框，支持JSON和文本。导出包含全部符合当前筛选的记录，按ID正序排列，包含筛选条件、导出时间、记录数、保留策略及结构化数据，不受界面分页限制。取消不写文件；写入失败明确提示。导出行为本身在文件成功保存后新增一条日志，因此不包含在此次已生成的快照中。

## IPC与诊断入口

|命令|参数|结果|
|---|---|---|
|`workbench_logs`|`filter: {since?,until?,module?,level?,keyword?,task_id?}`, `beforeId?`, `limit?`|`{rows,total,next_before_id,retention_days,max_rows}`；limit限制为1–500|
|`workbench_export_logs`|同一`filter`，`format: json/txt`|原生保存后返回`{path,count}`，取消返回null|
|`workbench_ui_error`|有限`kind`及错误说明|脱敏后归入应用模块|

所有时间为epoch秒。页面的结束时间为输入时刻本身；不自动延长到当分钟结束。旧记录没有结构化字段时返回空对象。

`workbench_ctl <数据库> logs [筛选JSON文件]` 查看最近100条及匹配总数。`workbench_ctl <数据库> export-logs <筛选JSON文件> json|txt <绝对路径>` 使用相同导出实现，便于专机诊断；该入口不触发采集请求。
