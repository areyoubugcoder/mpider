# 主页同步与会话恢复

主页同步是跨页面的后台监测服务。首次开启后，切换页面、采集完成、窗口关闭到托盘均不关闭服务；主动关闭、微信连接异常或应用退出时状态真实变更。底栏常驻状态和开启/关闭入口。应用重启不静默附加微信；任务的新采集意图可以在首次会话过期时自动开启监测。

## 用户流程

点击首页同步、获取下一页或继续历史任务后，若服务端明确返回会话过期或认证失败，后台保留原任务并自动启动主页监测。监测就绪后，全局提示目标公众号名称和“请在微信打开该公众号主页”。用户手动打开主页，已打开的页面可重新进入或刷新；收到完整新会话后自动继续原任务，无需再次点击继续。

程序只负责启动监测、接收新会话和恢复任务，不搜索、点击、刷新或打开微信窗口，不操作剪贴板，不周期访问主页保活；不自动最大化、最小化、恢复窗口或抢占焦点。窗口控制脚本不属于此恢复链路。

后台状态和恢复入口在各业务页面均可见，区分监测准备、等待用户打开主页、首页已收到但会话未齐和准备继续。监测未就绪时不催促用户打开。首次更新后仍失败时停止循环，显示“更新会话并继续”。同步开启不表示服务端会话永不过期；不根据游标年龄或固定会话 TTL 猜测失效。

## IPC 与持久化

- `workbench_home_sync_start(pythonPath)` 幂等开启监测，已启动时不重复附加，也不改变当前采集范围。
- `workbench_discovery_start(pythonPath,target)` 仅接受 `target=null`，保留旧调用兼容；采集范围改在各公众号的历史采集弹窗配置。监测不自动创建采集任务。
- `workbench_recover_session(id,pythonPath)` 注册显式恢复意图。已有不同于失败版本的新会话时直接恢复；否则绑定监测运行、目标公众号、原会话与请求时间，等待用户新打开的主页。重复调用在等待阶段幂等。
- `TaskProgress.session_recovery` 保存 `discovery_id`、`requested_at`、`previous_session_id` 和 `phase`。等待阶段为 `starting / waiting_home / preparing_session`；结束为 `resumed / interrupted`。旧记录字段缺失按未知读取。
- `Discovery.scope_started_at` 只保留旧数据读取兼容。普通 IPC 不包含密钥、原始游标或完整协议载荷。

只有同一监测运行中、恢复请求之后发起的目标公众号首页，在完整新会话保存后才能自动续采。仅收到首页、其他公众号、旧请求晚到、旧监测运行晚到，均不能触发。会话保存与恢复原任务在同一数据库事务提交；不增加外键。

单页任务保留入队时绑定的游标；篇数与日期任务保留历史检查点和缓冲。新首页更新当前首页快照，不覆盖上述进度。固定会话实验不自动更换会话，避免破坏实验条件。

## 观察与计账

监测工作进程只接收停止指令，不包含 GUI 自动化模块或导航命令。原生请求按 callback 与公众号身份关联，歧义响应不入库。实际主页响应和完整会话才是更新成功的依据。

启动监测和等待主页本身不发起列表请求、不占用请求预算。用户在微信发出的列表请求按观察记录计账，同一观察事件重复投递不重复计数；这些用户请求无法由软件拦截或限速。自动续采仍持有工作台共享列表锁，遵守持久化间隔、预算及冷却许可。

用户暂停或取消任务、关闭同步、连接中断和应用重启都会撤销自动继续意图。迟到的准备完成事件不得重新开启已关闭的同步；观察器停止后有界回收子进程。已经发送的请求仍保留账本与证据。

## 验证

离线进程集成测试覆盖：真实子进程管道返回会话过期 → 自动启动监测 → 等待期间不下发导航命令、不发请求 → 模拟用户打开主页并交付完整新会话 → 用原游标续采。它不替代微信真机验证。

构建、离线回归与真实采集分别验收；没有获得用户手动打开主页后的真实响应时，不声称完整恢复流程已通过。具体口径见 [验证范围](windows-workbench-validation.md)。

## 按公众号操作更新

监测现在仅登记公众号、首页游标和完整会话；文章不会随监测自动入库。新增 `home` 首页任务与历史任务共同使用会话恢复，`home_sync` 请求不携带分页游标，成功后只入库首页文章并更新当前游标；历史检查点、缓冲和实验保持不变。详见[按公众号操作](source-actions.md)。离线协议测试不替代真实微信验收。
