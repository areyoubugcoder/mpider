# 多公众号持续识别与采集契约

开启独立的公众号监测开关后，在微信手动打开主页。全部监测到的公众号进入列表；监测只登记身份、首页游标和完整会话，不入库文章、不自动创建历史任务，不操作微信 GUI、不改变任何窗口状态。缓存页面没有新请求时继续等待。采集与同步使用[按公众号操作契约](source-actions.md)。

列表合并已有公众号，按最近监测或采集时间倒序，显示实际入库篇数、会话登记状态、首页同步与历史任务状态。即使文章为零或会话材料未齐，公众号也显示在列表。操作列提供首页同步、历史采集、正文下载与导出；历史范围只属于选定公众号。没有全局采集范围，也没有批量监测后自动采集的隐式行为。

本地 IPC：`workbench_home_sync_start(pythonPath)` 幂等开启监测，旧 `workbench_discovery_start(pythonPath,target)` 仅接受 `target=null`。`workbench_discovery_stop()` 停止观察，已创建的独立任务继续。快照中的 `discovery.accounts` 只记录观测与会话准备状态；历史 `target/task_id` 字段保留读取兼容，不再驱动创建任务。密钥、原始游标与保护文件路径不进入普通 IPC。

首页同步和历史任务会话过期时，按[会话恢复契约](home-sync-recovery.md)自动启动监测，提示用户打开目标主页；完整新会话到齐后继续原任务。关闭或退出不静默重新附加微信，新用户采集意图可以在缺少会话时启动监测。

原生请求按 callback 和响应公众号身份关联，多个同身份在途请求仍有歧义时拒绝入库，不能按最近窗口猜测。首页仅接受 ActionType=0 且无 Offset 的成功列表响应。所有观察到的原生列表请求计入共享账本；这是用户在微信发出的请求，软件无法阻拦或限速。独立翻页仍受统一间隔、预算及冷却控制。观察器退出后卸载脚本并回收子进程。运行记录最多保存100条固定阶段名与时间，涵盖启动、附加、脚本加载、就绪、停止和进程回收，不记录密码材料。

实验室仅显示每公众号统一的当前游标，显示返回该游标的页码和下一页。页码只沿有证据的父子链标记。下一页操作创建单页任务，不消费已有缓冲；成功返回新游标后新年龄从其获取时间开始。失败和实验复测不重写获取时间。年龄不等于已证明的有效期。新实验默认固定该公众号最新会话，已有实验会话不改变。

验证分别记录本地状态/关联测试、Windows 构建和真实 GUI 操作；CLI 成功不能替代 GUI 验证。

## 当前游标统一规则（2026-10-22）

`Source.current_cursor_id/current_cursor_at` 是公众号页、实验室和手动下一页共同使用的唯一当前游标指针。新首页识别或正式采集收到新游标时，在保存证据的同一事务中更新该指针；所有页面从同一快照读取，年龄统一使用对应 CursorRecord.observed_at 计算，失败、点击和实验复测不重写年龄。历史检查点仍单独用于日期/篇数任务的恢复，避免重识别首页清空历史进度；不再将历史检查点冒充当前游标。

`workbench_next_page(biz)` 在事务内选择当前游标并写入单页任务的 `target.cursor_id`；执行及响应页码均使用该固定父游标。当前游标与历史检查点分叉时，单页动作只保存文章和当前游标，不覆盖原历史检查点/缓冲；若两者原本相同则正常推进历史。实验室固定实验不随当前指针切换，实验的验证请求不更新当前游标。没有新游标的末页将当前指针清空。

旧数据只从已有首页/历史游标的观测时间选取最新记录，不根据导入顺序或较大的游标ID判断新旧；旧末页无法确认当前游标时保守保持为空，等待再次识别。

单页任务结果明确区分实际响应篇数与新入库篇数。`TaskProgress.received_articles` 为可空字段；新任务累计实际解析的响应文章数，旧任务缺少此前计数时保持未知。实验室同时展示最近单页任务结果；请求失败不改游标获取时间。关键任务、请求和游标变化进入可筛选导出的[系统日志](system-logs.md)。

公众号监测入口位于公众号页独立卡片，底栏显示只读状态，服务保持开启与采集范围分开管理；会话恢复不要求用户手动切换页面或回到任务页再次继续。见 [主页同步与自动恢复](home-sync-recovery.md)。
