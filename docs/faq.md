# 常见问题（FAQ）

适用于当前 Windows 工作台预览版。下面区分已验证的范围、使用中遇到的风险与尚无结论的问题，不提供免封控承诺。

## 验证过哪个微信版本？其它版本可以直接用吗？

当前工作台仅以 **Windows 微信 4.1.15.56 x64** 完成相关采集验证。需要 Windows x64、WebView2，以及独立运行说明要求的 Python/Frida 环境。

程序会检查微信模块摘要与函数指纹，匹配后才运行。仓库保留的其它版本适配不代表当前工作台已完整验证；微信升级后可能无法监测或采集，不能只修改版本号强行运行。Frida 附加已有微信退出记录，长期稳定性仍待验证。

## 使用家宽 IP 下载正文，也会被屏蔽吗？

**会有这种风险，家宽 IP 不等于安全通行证。** 使用中频繁下载正文可能遇到验证页、拒绝访问或临时屏蔽；同一出口下的正文、图片及其它访问也可能共同影响访问情况。

遇到异常时先暂停下载，查看日志，降低正文与图片并发、拉长间隔，等待后再检查。不要连续重试，也不要把频繁切换网络当作恢复方案。没有已经验证的统一安全下载量或固定恢复时间；单次失败也不能直接判定为 IP 被封，文章删除、链接失效和网络故障同样可能导致失败。

## “限流配置”能告诉我账号的安全采集上限吗？

**目前没有稳定结论。** 限流配置记录本程序观察到的请求、结果、预算与冷却，帮助排查问题，不能精确判断微信的账号阈值、全部后台流量或最终封控原因。

旧 getmsg 接口曾出现约 200 次/24 小时的历史样本，这些结果不能套用到当前原生列表、正文或图片链路。软件初始间隔、预算、并发只是本地节制参数，不是平台公布或已证明安全的配额；预算未用完也可能遇到限制，重启程序不会重置服务端限制。

## 默认抓取频率与预算是最佳配置吗？可以自行调整吗？

**不是最佳配置，可以自行调整。** 当前默认值只是初始配置，不是微信公布或已经验证的安全阈值。在“限流配置 → 抓取频率与预算”可以查看说明、调整并保存；已保存配置以界面为准。

列表间隔控制发送频率，近 24 小时列表预算按滚动窗口累计、跨公众号和实验共享；正文与图片分别受各自间隔和并发控制，增加并发不会绕过同类间隔。预算不是文章篇数，正文与图片也不消耗列表预算。

请根据实际需求、网络环境和请求记录逐步调整。验证页或拒绝访问增多时，先暂停并降低负载，避免连续重试。新配置从下一次尚未发送的请求生效，保存配置不会清除已有请求记录、冷却或服务端限制。

## 为什么先要开启公众号监测？开启后会自动下载文章吗？

先在“公众号”页首卡片开启监测，再在已登录的微信中手动打开目标公众号主页。监测负责登记公众号、会话及游标，不自动把文章入库或下载正文。

登记后，在对应公众号行分别发起首页同步、历史采集和正文下载。初次监测及补充新会话需要可交互的桌面；程序不会替你操作微信窗口。

## 提示会话过期，是否表示历史游标也失效了？

不一定。会话认证失败与游标不可复用是两件事，没有统一的固定有效期结论。按任务提示更新会话，并在微信手动打开目标公众号主页；完整新会话到齐后，等待恢复的任务会沿原检查点尝试继续。

已有单个公众号旧游标在 33 小时 19 分后用新会话成功复用的记录，但不能推广为所有公众号或所有游标的最低寿命。任务暂停、取消或关闭监测后，也不要假设仍会自动继续。

## 实验室有什么用？开启后会影响正常采集吗？

实验室用于固定游标和会话，按计划发送真实请求，观察旧游标能否继续使用，帮助区分会话问题与游标不可复用。默认隐藏，可在“系统设置 → 系统配置 → 显示实验室”开启；普通采集无需使用。

固定实验只保留验证证据，不把文章写入正式文章库或推进历史检查点，但会消耗共享预算并影响其它列表任务的等待时间。“获取下一页”则是真实单页采集，可能入库文章、更新当前游标，两者不要混淆。

结果只代表实际请求下的可用年龄或证据区间，不是统一 TTL 或账号安全阈值。关闭入口不等于停止实验，需要在实验过程中手动终止；完整操作、结果解读与报告隐私见实验室页面顶部的“实验室说明”。

## 文章、公众号信息和日志存在哪里？会上传给项目维护者吗？

当前工作台把公众号信息、文章、正文、图片、任务、请求账本、设置和日志保存在本机应用数据目录。可在“系统设置”查看目录；Markdown 与 HTML 导出写入你选择的位置。

当前工作台不要求注册 MPider 账号，不自动向维护者上传采集数据、数据库或诊断材料。仓库保留的旧版上报与通知能力是另一套可选实现；使用旧入口、自行改造或启用相关配置时，应另行检查发送内容和接收方。

## 软件会访问哪些外部服务？广告会带走我的数据吗？

采集会访问微信服务和文章图片来源。底部广告位在应用启动及每 30 分钟从 GitHub 读取公开 JSON 配置，不携带 Cookie、微信账号、采集记录、日志或会话材料；GitHub 仍会收到访问 IP 等常规网络信息。没有广告曝光统计或点击上报。

只有点击广告、原文或 GitHub 链接时，系统浏览器才访问对应网站；浏览器自身的登录态与目标网站的隐私规则另行适用。MP2Rss、历史文章下载等是独立服务，MPider 不把本地文章库或微信会话交给它们。关于弹窗与本页内容随应用提供。已配置签名公钥的正式 Windows 安装版启动时检查公开更新清单，不自动下载或安装；默认未配置公钥的构建不检查更新。

## 微信会话和本地文章是否都已加密？可以直接把数据库发给别人吗？

会话密钥、原始游标与协议证据使用当前 Windows 用户的 DPAPI 保护，普通界面和日志不直接返回这些原始材料。DPAPI 不能防止以同一用户权限运行的恶意程序，也不能把受保护文件直接复制给另一位用户继续使用。

**文章、图片、日志和普通导出不是加密保险箱。** 它们可能包含公众号名称、文章标识、本地路径与正文。不要公开数据库、完整数据目录、workbench/private/、会话文件或原始抓包；反馈时只提供经过检查和脱敏的必要片段。请自行管理备份、设备权限和导出文件。

## 项目是否有账号池、共享微信号或自动轮换账号？

**当前工作台不提供内置公共账号池、共享微信号、云端托管账号或自动轮换账号服务。** 采集使用你自己电脑上已登录微信的会话，需要自行承担该账号的访问风险。

仓库保留的旧版多微信号登记与单激活切换代码，不等于项目提供账号资源或已验证的自动轮换方案。不要把多账号、换号、换 IP 当作规避限制或保证持续采集的办法。

## 是否会采集聊天记录？为什么会话材料仍然敏感？

当前功能针对公众号文章列表、正文与图片，不提供聊天记录采集功能。原生监测通过 Frida 附加本机微信进程，相关权限和会话材料仍然敏感，不应交给不可信程序或他人。

建议在自己控制的专机上运行可信来源的构建，核对文件校验值，并妥善保护应用数据目录。日志脱敏与 DPAPI 不能消除进程附加和同用户权限带来的全部风险。

## 下载、导出和备份有什么区别？

下载把正文和图片保存在本机，已有正文不会重复下载；导出将已下载的内容同时写成 Markdown、HTML 与图片文件，不会隐式补采缺失正文。单篇、批量和整号导出都要求目标文章已有本地正文。

完整备份需要保留应用数据目录，不能只复制数据库而遗漏正文、图片或受保护文件。普通导出不读取受保护会话文件，也不能替代任务状态和受保护会话的备份。正文及正文链接可能带有原文章内容中的敏感参数，不是自动脱敏材料，分享前需要检查。

## 关闭窗口后还会继续运行吗？旧 getmsg 链路还需要代理和证书吗？

关闭主窗口会收起到系统托盘，后台任务仍可能继续；需要结束程序时请从托盘选择“退出”。电脑休眠、退出应用或微信状态变化可能中断任务。

当前原生工作台不需要安装根证书或切换系统代理。旧代理/getmsg 实现作为历史代码保留，其列表接口自 2026-09-10 起不可用；不要把旧版配置和错误码解释当作当前工作台的操作指南。
