# 删除公众号与关联数据

公众号列表的“删除公众号”需要二次确认。确认后不可撤销地删除该公众号所有文章行（包含此前从文章库删除的文章）、正文、评论、阅读缓存及本地图片；该公众号从公众号列表和文章筛选中移除。不对其他公众号进行删除，也不发送微信请求。

该号未结束的首页、历史、单号下载任务和运行中的实验会取消；跨公众号下载任务仅剔除该号文章，保留其他文章继续执行。混合下载任务的总量和完成列表随剩余文章调整，失败、缺图及跳过计数根据剩余文章的归档证据重新计算，无法确认完成的文章重新排队，后续结果继续累计。已结束的任务、请求账本、实验记录、受保护会话与游标证据留作审计。用户此前自行导出的文件属于用户选择的位置，不由删除操作清理。本操作不承诺安全擦除 SQLite 空闲页、系统备份或外部副本。

重新添加时，在监测开启的情况下重新打开该公众号主页。监测使用原始请求发出时间而非响应抵达时间判断是否发生在删除之后；删除前发出的响应会被忽略，缺少请求时间的旧版消息也不能复活已删除公众号。删除时间是亚秒精度的 Unix 时间，严格大于删除时点的主页请求才可重新登记；时钟回退时应等待时钟恢复后重新打开主页。

## IPC 契约

`workbench_delete_source({ biz: string })` 返回：

```json
{
  "deleted_articles": 123,
  "cancelled_tasks": 2,
  "cancelled_experiments": 1,
  "cleanup_pending": 0
}
```

- `deleted_articles`：数据库中实际删除的文章行数，包含此前逻辑删除的行。
- `cancelled_tasks`：本次取消的工作台任务数，不计仅缩减目标的混合下载任务。
- `cancelled_experiments`：本次取消的运行中实验数。
- `cleanup_pending`：当前仍需重试的文章缓存目录数。文件被占用、权限限制等不会回滚已提交的数据删除，前端应明确提示尚有缓存待清理。待清理队列持久化，归档后台循环会重试，重启后继续。

空标识、超长标识、账号已删除或不存在会返回中文错误；事务失败不提交任何数据库修改。此接口不接受任意磁盘路径，缓存清理只使用存储层记录的文章 ID，在应用工作台数据根目录下定位缓存。

## 在途结果保护

取消任务、删文章、清空覆盖集合和登记删除时点位于同一事务，已取消的任务不能被旧副本保存为运行态。混合下载的目标集合以数据库中持久化值为准，旧 worker 不得把删除项重新加入。正文更新以不可复用的自增文章 ID 进行，不再通过 `upsert` 重建旧文章；即使重新登记同一公众号，新文章也得到新 ID。归档记录写入也再次校验文章存活。

归档每次创建目录、落盘正文/图片及清单均通过文章存活检查，并持有与删除共用的 SQLite Immediate 写事务屏障。删除前已进入屏障的写入先完成再清理，删除后晚到的结果不能重新创建缓存。缓存清理失败项保留在持久化队列中。

验证使用内存数据库和临时目录，覆盖混合下载隔离、全部正文与评论删除、旧首页/历史响应拒绝、重新登记后旧文章 ID 拒绝写回、并发落盘屏障及目录清理；没有操作真实公众号数据。
