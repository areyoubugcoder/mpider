# 原生链路适配与验证方法

当前工作台的 Windows 原生观察器与独立会话请求方案见 [实现原理](how-it-works.md) 和 [协议设计](wechat-session-protocol.md)。本页说明适配方法，不包含本机连接信息或真实采样记录。

## 适配边界

1. 核对微信版本、架构、模块 SHA-256、函数指纹与桥协议。相同版本号也必须核对摘要；未知指纹拒绝运行。
2. 从业务方法及协议字段定位语义边界，结合 PE 可执行段、函数边界与反汇编核对。不要平移复用旧版 RVA。
3. 校验内存范围、字符串长度和容量后再解析；越界、歧义或结构变化均停止。中间采样点不能当成普通函数入口使用返回钩子。
4. 只关联目标窗口中唯一在途列表请求与响应，同时核对方法、回调编号、载荷类型与公众号身份。回调编号不是全局请求 ID。
5. 用户手动触发主页后，分别验证首页、下一页请求游标、响应游标推进及去重。缓存内容和重复首页不能当成独立翻页证据。

## 数据一致性

客户端账号和文章链接 `__biz` 分别核对。保留完整文章链接，以 `(biz, mid, idx)` 去重，不自行拼装链接或生成游标。认证成功后仍需核对业务返回码，非零返回、空载荷、身份变化与游标未推进必须分别处理。

独立请求先持久化计账再许可发送。文章、检查点和成功状态原子提交。监测只登记会话和公众号，首页同步不覆盖历史进度。会话更新后继续原检查点，不把新首页游标替换为历史进度。

## 验收顺序

先运行虚构夹具的解析、身份校验、重复回调、认证篡改、事务回滚、预算与重启恢复回归，再在明确授权范围内做最小真机验证。真实采样材料与机器配置保留在仓库外。

默认间隔和预算只是本地控制初值，不是平台安全配额；未确认的错误码保留原值，不套用旧接口语义。短时成功、长期运行、安装升级与版本兼容性应分别记录，见 [验证范围](windows-workbench-validation.md)。
