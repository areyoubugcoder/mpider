# 抓取频率与预算说明

**系统默认值只是初始配置，并非最佳配置，也不是平台公布或已经验证的安全阈值。** 可根据实际文章量、网络环境和运行记录自行调整，在“限流配置 → 抓取频率与预算”保存。当前没有适用于所有账号或 IP 的最佳组合，不建议只以速度或跑满预算为目标。

## 每个参数控制什么？

| 参数 | 含义 | 当前初始值 |
|---|---|---|
| 列表最小／最大间隔 | 列表请求在这个范围内随机等待；首页同步、历史采集和实验共享列表闸门 | 90～120 秒 |
| 近 24 小时列表预算 | 本机工作台近 24 小时累计列表请求额度，跨公众号共享，不是每个号各一份 | 60 次 |
| 文章下载间隔 | 每个文章请求工作位在网页请求结束后等待的时间；空闲工作位的首个请求立即发送 | 1 秒 |
| 近 24 小时文章下载预算 | 全部公众号共享的文章页请求预算；包含推送解析、文章下载、跳转及失败重试，不包含图片 | 86,400 次 |
| 文章中图片请求间隔 | 文章封面与正文图片的发送间隔 | 1 秒 |
| 文章下载并发／图片并发 | 同时处理的工作数上限；文章请求工作位各自等待完成后的间隔，图片另有全局发送间隔 | 各 4 |
| 文章／图片重试次数 | 一个资源首次请求失败后的额外重试上限；重试也是网络请求 | 2 次 |
| 每任务自动重建上限 | 确认旧历史游标不可复用后，允许从首页重新定位历史边界的次数 | 1 次 |
| 异常访问冷却 | 命中相应异常信号后，本程序暂停发送新请求的冷却时长 | 300 秒 |

表中是新配置的初始值，已保存的配置以界面为准。列表预算按请求次数计算，不等于文章篇数；实验基线、复测、失败对照、重建及已观察到的原生列表请求也会占用额度。文章与图片另行记账，不消耗列表预算；文章解析与下载共同消耗文章预算，图片不消耗文章预算。

## 何时生效与恢复？

- 推送解析不单独设置每小时上限，在“限流配置 → 文章下载”与文章下载一起调整；旧版已记账的推送网页请求也计入文章预算。
- 文章下载与推送解析共用文章请求工作位。并发为 1 时：立即请求 → 网页响应结束 → 等待文章下载间隔 → 下次请求。并发大于 1 时，各工作位独立执行这一流程；间隔不从发送时间提前计算。失败、跳转与重试同样经过工作位和预算控制。已等待的时间也计入间隔，空闲后不重复等待；图片处理可以与文章请求等待并行。
- 保存后从下一次尚未发送的请求生效；已发送请求不会被撤回，保存配置也不会清除现有请求记录或正在进行的冷却。
- 24 小时是滚动窗口，不是每天零点重置。额度用完后等待旧请求移出窗口，相关任务再按实际状态和调度条件继续。
- 间隔设为 0 表示不额外等待，不表示取消预算、并发或其它访问限制。文章下载并发、图片并发各允许 1～12；列表预算和文章下载预算都必须为正整数。
- 冷却结束只表示本程序可以再次尝试，不保证微信侧已经解除限制。修改预算、退出或重启程序都不能重置服务端限制。

## 怎样自行调整？

先根据实际需要选择较低负载，每次只调整一类参数，结合请求明细中的实际间隔、结果、失败情况及任务进度观察。文章下载较多或家宽出现验证、拒绝访问时，应先暂停，降低文章下载与图片并发、拉长间隔，避免连续重试。

列表预算和请求间隔需要一起考虑，文章还可能带来多张图片请求。单纯拉大预算或减小间隔不保证更高的有效吞吐；默认配置不保证适合你的网络，调整后的配置同样没有免封控承诺。
