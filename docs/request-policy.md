# 抓取频率与预算说明

**系统默认值只是初始配置，并非最佳配置，也不是平台公布或已经验证的安全阈值。** 可根据实际文章量、网络环境和运行记录自行调整，在“限流配置 → 抓取频率与预算”保存。当前没有适用于所有账号或 IP 的最佳组合，不建议只以速度或跑满预算为目标。

## 每个参数控制什么？

| 参数 | 含义 | 当前初始值 |
|---|---|---|
| 列表最小／最大间隔 | 列表请求在这个范围内随机等待；首页同步、历史采集和实验共享列表闸门 | 90～120 秒 |
| 近 24 小时列表预算 | 本机工作台近 24 小时累计列表请求额度，跨公众号共享，不是每个号各一份 | 60 次 |
| 正文／图片请求间隔 | 两类请求分别限制发送频率；同类任务和重试共享间隔 | 各 1 秒 |
| 正文／图片并发 | 同时处理的工作数上限；增加并发不会绕过同类发送间隔 | 各 4 |
| 正文／图片重试次数 | 一个资源首次请求失败后的额外重试上限；重试也是网络请求 | 2 次 |
| 每任务自动重建上限 | 确认旧历史游标不可复用后，允许从首页重新定位历史边界的次数 | 1 次 |
| 异常访问冷却 | 命中相应异常信号后，本程序暂停发送新请求的冷却时长 | 300 秒 |

表中是新配置的初始值，已保存的配置以界面为准。列表预算按请求次数计算，不等于文章篇数；实验基线、复测、失败对照、重建及已观察到的原生列表请求也会占用额度。正文与图片另行记账，不消耗这项列表预算。

## 何时生效与恢复？

- 保存后从下一次尚未发送的请求生效；已发送请求不会被撤回，保存配置也不会清除现有请求记录或正在进行的冷却。
- 24 小时是滚动窗口，不是每天零点重置。额度用完后等待旧请求移出窗口，相关任务再按实际状态和调度条件继续。
- 间隔设为 0 表示不额外等待，不表示取消预算、并发或其它访问限制。正文并发、图片并发各允许 1～12；列表预算必须为正整数。
- 冷却结束只表示本程序可以再次尝试，不保证微信侧已经解除限制。修改预算、退出或重启程序都不能重置服务端限制。

## 怎样自行调整？

先根据实际需要选择较低负载，每次只调整一类参数，结合请求明细中的实际间隔、结果、失败情况及任务进度观察。正文下载较多或家宽出现验证、拒绝访问时，应先暂停，降低正文与图片并发、拉长间隔，避免连续重试。

列表预算和请求间隔需要一起考虑，正文还可能带来多张图片请求。单纯拉大预算或减小间隔不保证更高的有效吞吐；默认配置不保证适合你的网络，调整后的配置同样没有免封控承诺。
