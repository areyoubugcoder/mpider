摘要：以出差前整理系列教程为例，说明下载、双格式导出、整目录复制与缺图检查。

账号是自己的，风险自己承担，导出文章却还要额外付费。这种体验，我不认同。

因此，MPider 选择免费开源，把核心采集逻辑和凭证处理公开出来供核查，把知情权和选择权交还给用户。它的核心用途很直接：公众号监测，以及下载公众号文章的正文和图片。保存到本机后可以离线阅读，也能一次导出 Markdown 和 HTML。

今天回答一个具体问题：文章在 Windows 电脑上下载好了，出差时想换到另一台电脑阅读，应该带走哪些文件？

先说结果：带走完整导出文件夹

例如，你准备在路上复习一个公众号的系列教程。使用 MPider 下载需要的正文和图片，再导出到一个专用文件夹。把这个文件夹完整复制到另一台电脑，双击里面的 index.html，就能从目录进入已导出的文章，也可以搜索标题。

HTML 适合用浏览器阅读，Markdown 方便在支持它的编辑器里查看、整理自己的笔记。两种格式一次生成，不用分别导出。

按这个顺序操作

1. 在 MPider 的“公众号”页开启“主页识别”，到已登录的微信里手动打开目标公众号主页，登记公众号与会话。这个登记步骤本身不会采集文章。
2. 在该公众号行点击“同步最新文章”获取首页列表；系列旧文需要往前找时，使用“采集历史文章”，按追加篇数或截止日期建立任务。需要更新会话时，按提示手动重开主页；历史任务支持检查点续采。
3. 在文章库找到目标文章，单篇或勾选下载正文与图片。只准备几篇阅读材料，就只选择需要的篇目；准备整号资料时，可使用“下载全部正文”。
4. 确认所选正文下载完成，再执行单篇、勾选或整号导出，选择保存目录。整号入口是公众号列表操作列的“导出所有文章”。导出范围是该号本地已入库文章，不会顺便补齐所有历史。
5. 导出完成后，打开 index.html 检查文章与图片，再把完整目录复制到另一台电脑。不要只拷贝某一个 HTML 或 Markdown 文件。

为什么不能只拿走正文文件？

导出目录里，index.html 是阅读目录，articles 文件夹保存 HTML 和 Markdown，images 文件夹保存共用图片；另外还有 manifest.csv 清单和 README.txt。

文章与图片依靠相对路径配合。只复制正文文件，可能丢掉配图。保留目录结构、整包文件夹一起移动，才能保留这套阅读材料的文件关系。导出生成的是文件夹，不会自动生成 ZIP；如需压缩，可在导出后自行压缩完整目录。

导出只使用已保存到本地的图片，不会在阅读时替你补下未保存的图片。发现缺图时检查文章提示和 README.txt；清单显示正文导出成功，也不代表每张图片都齐全。视频、音频、复杂交互和付费全文不在这次导出范围内。

公众号监测负责什么？

要先登记公众号与历史采集会话，用“主页识别”：开启后仍需自己手动打开公众号主页。

v2.0.1 另有独立的“推送监测”，用于发现本机已登录微信中的文章链接；开启“开始处理”后，符合身份与时间条件的文章去重加入文章库。入库后仍需另行下载正文，才能制作离线阅读材料。它不保证收全推送、离线补齐或全天自动订阅，按公众号定时增量采集仍是计划方向。

阅读材料和应用备份各有用途

导出方便带走已保存文章，不能恢复全部任务进度与受保护会话。若要保留应用数据，应按项目说明备份“系统设置”显示的完整数据目录。

当前正式客户端要求 Windows 10/11 x64、WebView2，以及已验证的微信 4.1.15.56 x64；微信升级后需要重新适配。开源、本地运行和低频请求都不能保证账号安全或防封，避免使用承载重要联系人、工作或支付用途的账号。

只处理你有权保存的内容。正文和普通导出不加密，分享前自行检查内容与链接，勿把应用数据库、会话文件当成阅读材料发出。
