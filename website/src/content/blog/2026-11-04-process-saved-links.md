账号是自己的，风险自己承担，导出文章却还要额外付费。这种体验，我不认同。

因此，MPider 选择免费开源，让核心采集逻辑和凭证处理可供核查，把知情权和选择权交还给用户。它的核心用途很直接：公众号监测、公众号文章下载，正文和图片留在自己的电脑，下载后离线阅读，再同时导出 Markdown 和 HTML。

今天介绍已公开的 v2.0.1：停止发现新链接后，已保存的链接还能继续处理。

一个场景：上午发现链接，稍后再整理

比如，你上午在 Windows 微信里阅读几个公众号，MPider 已发现并保存了一批文章链接。稍后不想继续扫描新链接，但想把已有的内容处理完。

进入左侧「推送监测」，现在可以分别控制两件事：

“开启推送监测”负责发现并保存本机微信中的新文章链接。仅开启这一项，不会请求文章网页。

“开始处理”负责读取已保存的链接，获取网页，核对公众号、标题和发布时间。符合范围与时间窗的文章去重加入文章库。这一步不需要继续开启监测，也不要求微信保持运行；电脑、MPider 和网络仍需可用。

按这个顺序操作

1. 在 Windows 上保持微信登录，进入「推送监测」，选择范围并开启监测，积累需要处理的链接。
2. 需要把已有链接入库时，点击「开始处理」。可以边发现边处理，也可以停止监测，只继续处理已保存链接。
3. 想暂缓处理时，点击「暂停处理」，未完成链接会保留。再次开始处理，继续已有队列。
4. 文章入库后，到文章库下载需要的正文和图片。目标正文下载完成，再使用阅读和导出入口，得到 Markdown、HTML 和已保存的图片。

链接进了队列，不代表正文已经下载；文章入库后，仍按自己的需要选择下载。已有正文会跳过，批量或整号导出前要先完成全部目标正文下载。

需要旧文时，仍走主页识别和历史采集

在「公众号」页开启「主页识别」，再在微信手动打开目标公众号主页，登记公众号与会话。主页识别本身不采集文章。登记后，按需同步首页，或按追加篇数、截止日期创建历史采集任务。

推送监测不能保证补齐离线期间的所有文章；手动打开的旧文也可能被发现，“发现时间”不是微信推送送达时间。应用重启后，扫描和处理两个开关均保持关闭，需要按需重新开启。

使用前，确认环境与风险

当前 Windows 客户端需要 Windows 10/11 x64、WebView2，已验证微信 4.1.15.56 x64，微信升级后需要适配。不要把可处理已保存链接理解成 macOS 或 Linux 可以扫描微信进程；正式客户端仍面向 Windows。

所有使用个人微信号的客户端都可能有封号风险，MPider 也不例外。开源、本地运行和低频请求都不能保证账号安全，请避免使用承载重要联系人、工作或支付用途的账号，只保存自己有权处理的内容。暂不采集视频、音频、评论、阅读量和互动数据；按公众号定时增量采集仍是后续计划。
